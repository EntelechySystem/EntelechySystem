# 开发者指南（EntelechySystem）

> 文档定位：面向参与 ES（EntelechySystem）开发的贡献者，介绍仓库结构、核心入口、配置体系、开发约定与常见问题。

## 1. 项目概览

**生机系统（Entelechy System, ES）** 是一个面向通用人工智能探索的多子系统工程，实现上以 Python 为主体，并在仓库中沉淀运行态数据结构（`workstage/`）与多类库（`EntelechySystem_python/Libraries/`）。

当前仓库版本信息（见根目录 `pyproject.toml`）：`0.0.8_alpha`。

## 2. 运行与环境

### 2.1 Python 版本

- 需要 Python `>= 3.12`（见根目录 `pyproject.toml`）。

### 2.2 依赖安装

仓库同时提供：
- `pyproject.toml`（声明依赖范围，偏“上游约束”）
- `requirements.txt`（固定版本，偏“可复现安装”）

在 Windows（PowerShell）上建议使用虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt
```

如果你使用 `uv`（`pyproject.toml` 中也配置了 index），可以用：

```powershell
uv sync
```

> 说明：本仓库存在两套依赖描述，实际使用时建议团队统一一种安装方式；如果你需要“最快跑起来”，优先使用 `requirements.txt`。

## 3. 仓库结构速览

### 3.1 顶层目录

- `EntelechySystem_python/`：Python 主体代码（模拟器、引擎、实验、库）。
- `workstage/`：运行阶段配置、模型与环境数据（其中 `workstage/config` 常作为默认配置目录）。
- `attachment/`、`draft/`、`library/`、`Resource/`：资料与草稿，通常不在开发任务中随意改动。

### 3.2 Python 代码目录（重点）

- `EntelechySystem_python/simulator.py`：模拟器入口函数 `simulator(config: dict)`。
- `EntelechySystem_python/Experiments/`：实验脚本入口示例（如 `EXP_test_010.py`）。
- `EntelechySystem_python/engine/`：引擎核心与工具集。
- `EntelechySystem_python/Libraries/`：配置、世界环境、模型、参数、系统等“库化”内容。

## 4. 核心入口与运行方式

### 4.1 推荐入口：实验脚本

已有一个可运行的实验脚本：
- `EntelechySystem_python/Experiments/EXP_test_010.py`

其核心流程为：构造一个 `config` 字典，然后调用 `simulator(config)`。

在仓库根目录执行（建议先激活虚拟环境）：

```powershell
python EntelechySystem_python\Experiments\EXP_test_010.py
```

### 4.2 模拟器入口：`simulator(config)`

`EntelechySystem_python/simulator.py` 的 `simulator` 会：

1. 计算项目根路径与引擎路径（通过 `Tools.get_project_rootpath()` 等）。
2. 选择配置加载方式：
   - 运行配置生成程序（`config_program.py`）并读取 `config.pkl`，或
   - 直接加载 `config.py`。
3. 将配置写入全局变量 `gb`（`EntelechySystem_python/engine/core/define_engineGlobalVariables.py`）。
4. 创建/准备实验输出目录（`SimulationsData/...` 一类结构），并导出 `gb.pkl`。
5. 根据开关决定是否运行“实验组模拟程序”等子程序。

> 关键点：模拟器通过配置中的“路径字段”把实验、系统、模型、世界环境等资源组织起来，因此开发者应优先理解与维护配置体系。

## 5. 配置体系（开发者视角）

### 5.1 配置目录

存在两类常见配置目录：

- `workstage/config/`：工作区配置（包含 `config.py` / `config.xlsx` / `config.pkl` / `config_program.py`）。
- `EntelechySystem_python/Libraries/ConfigsLibrary/config_test/`：示例/测试配置（实验脚本默认指向它）。

### 5.2 配置生成程序 `config_program.py`

配置生成程序的职责通常是：
- 在 `config.py` 与 `config.xlsx` 间互转（见 `DataManageTools` 的相关函数），并
- 导出 `config.pkl` 供模拟器快速读取。

当你修改了大量配置字段，且使用 PKL 方式加载时，需要重新生成 `config.pkl`。

### 5.3 常见配置字段（建议先掌握）

- `folderpath_config`：配置目录路径（相对项目根）。
- `foldername_engine` / `folderpath_relpath_engine`：引擎定位相关。
- `folderpath_system` / `folderpath_models` / `folderpath_world_environment` 等：库资源定位。
- `program_实验组模拟程序`：是否运行实验组模拟。
- `is_develop_mode`：开发模式（通常用于断点调试与在同进程内调用）。

## 6. 开发约定

### 6.1 变更范围

- 只修改与当前任务直接相关的文件，避免牵连式重构。
- 默认不改动资料类目录：`attachment/`、`draft/`、`library/`、`Resource/`。

### 6.2 Python 代码规范（建议）

- 新增/修改代码尽量补充类型标注。
- 文档字符串建议使用 Google 风格（中文说明，包含 `Args:` / `Returns:` / `Raises:` / `Examples:`）。

> 说明：仓库现存代码风格不完全统一，新增代码尽量“向更规范的一侧靠拢”，但避免大范围格式化旧代码。

## 7. 常见问题（FAQ）

### 7.1 运行卡住或无输出

- 检查配置中的 `is_prerun_config_program` 与 `is_use_xlsx_as_config_file` 组合。
- 某些配置注释指出：当 `is_prerun_config_program=False` 时，在某些运行方式下可能无法继续推进；建议用终端直接运行脚本，而不是仅在交互控制台。

### 7.2 输出数据在哪里

- 默认在配置里由 `folderpath_root_experiments`、`foldername_outputData`、实验命名策略共同决定。
- 运行后通常会在输出目录的 `config/` 下看到 `gb.pkl` 与拷贝出的配置。

## 8. 新增一个实验（建议流程）

1. 复制一个现有实验脚本（如 `EntelechySystem_python/Experiments/EXP_test_010.py`）。
2. 修改 `folderpath_config` 指向你的新配置目录（建议在 `EntelechySystem_python/Libraries/ConfigsLibrary/` 下创建）。
3. 如需不同世界环境/模型/系统，修改配置中的 `folderpath_world_environment`、`folderpath_models`、`folderpath_system` 等。
4. 运行实验并检查输出目录与日志。
